# CLAUDE.md

Guidance for Claude (and humans) working in this repository.

## Purpose

This repository holds the **source data** (tables of strings and media files)
and the **build scripts** that turn that data into [Anki](https://apps.ankiweb.net/)
flashcard decks for **young children**.

The repo is the single source of truth. Decks (`.apkg` files) are build
outputs, never edited by hand.

Audience: children who are **just learning to read and count, up to around
ten years old**. The youngest may barely read, so cards must be visual and
short, and every word card is spoken aloud; content can grow harder for
older children (longer words, larger numbers) via separate levelled decks.

## Deck categories

1. **Arithmetic** – simple sums such as `3 + 4 = ?`. Start with addition and
   subtraction within 10, then within 20; multiplication tables and larger
   ranges can follow for the older end of the age range. Arithmetic
   rows are generated by a script into a table rather than typed by hand, so
   the table stays reviewable and the deck stays stable.
2. **Picture → word (multiple choice)** – a picture is shown with several
   candidate words; the child picks the one that matches. The back reveals the
   correct word and plays its audio.

More categories may be added later; each category gets its own table(s) and
note type.

## Languages

All word cards exist in **Swedish (`sv`) and English (`en`)**.

- One concept table holds one row per concept (e.g. "cat") with both the
  Swedish and English word, so the two languages can never drift apart.
- Each language is built as its **own deck** (e.g. `Ord – Djur` and
  `Words – Animals`) from that shared table.
- Swedish text must keep `å ä ö`; all files are UTF-8.
- The written word always matches exactly what its recording says. If the
  recording says `katt`, the card shows `katt`; if it says `en katt`, the card
  shows `en katt`. Adjust the text to the audio, never the other way round.

### Word selection: media first

Every word card has **an image and audio in both Swedish and English**. Words
are chosen so that all three can be sourced: a concept is only added to a
concept table once `fetch_media.py` has found an acceptable image, a Swedish
recording and an English recording for it. Concepts missing any of them stay
out (they may be listed in `data/candidates/` while searching).
`build_decks.py` fails if a concept row lacks `image`, `audio_sv` or
`audio_en`.

## Repository layout (planned)

```
data/
  concepts/<topic>.csv      # one row per concept: id, sv, en, image, audio_sv, audio_en, tags
  candidates/<topic>.csv    # words still waiting for complete media
  arithmetic/<range>.csv    # generated: id, question, answer, distractors
media/
  images/<id>.<ext>         # downloaded pictures
  audio/<lang>/<id>.<ext>   # downloaded pronunciations
  sources.csv               # provenance + licence for every media file (see below)
scripts/
  fetch_media.py            # finds and downloads media, records provenance
  gen_arithmetic.py         # writes data/arithmetic/*.csv
  build_decks.py            # reads data/ + media/, writes build/*.apkg
templates/                  # Anki card HTML/CSS/JS
build/                      # .apkg output, git-ignored
ATTRIBUTION.md              # generated credits for all bundled media
```

Tables are **CSV, UTF-8, comma-separated, with a header row** so they diff well in git and open in any
spreadsheet.

Concept `id`s are lowercase English slugs (`cat`, `fire_truck`) and must
never change once published; they feed Anki GUIDs (see below).

## Tooling

- **Python 3** with [genanki](https://github.com/kerrickstaley/genanki) (MIT)
  to generate `.apkg` files.
- genanki rules that matter here:
  - Model (note type) IDs and deck IDs are hard-coded constants, chosen once
    and never changed; changing them makes Anki treat the deck as new.
  - Each note gets a stable GUID derived from the concept `id` and language
    (`genanki.guid_for(...)`), so re-importing an updated deck updates
    existing cards instead of duplicating them and keeps the child's progress.
  - Media files are passed via `Package.media_files`; filenames referenced in
    fields must be bare basenames (`<img src="cat.png">`, `[sound:cat_sv.mp3]`).
- **Multiple choice** is implemented in the card template with a little
  JavaScript (shuffle the choices, highlight the tapped answer) so no Anki
  add-on is required. Templates must be tested on
  Anki desktop, AnkiDroid and AnkiMobile, since those are where kids use it.
  Distractor words come from other concepts in the same topic.
- Keep dependencies minimal; pin them in `requirements.txt`.

## Media sourcing and licensing

Media is fetched **automatically** from repositories whose licences allow
**noncommercial redistribution**. This project is noncommercial, so
NonCommercial (NC) licences are acceptable, but every file must still meet its
licence's terms (attribution, ShareAlike).

Acceptable licences: CC0 / public domain, CC BY, CC BY-SA, CC BY-NC,
CC BY-NC-SA, MIT/Apache-style. Not acceptable: anything with NoDerivatives
(ND) if we resize/convert, "personal use only", unclear or missing licence.

Candidate sources:

| Kind   | Source | Licence | Notes |
|--------|--------|---------|-------|
| Images | [ARASAAC](https://arasaac.org/) pictograms | CC BY-NC-SA 4.0 | Made for children/AAC, consistent style, has an API with Swedish and English keywords. Primary image source. |
| Images | [OpenMoji](https://openmoji.org/) | CC BY-SA 4.0 | Consistent emoji style, good for animals/food/objects. |
| Images | [Openclipart](https://openclipart.org/) | CC0 | No attribution needed; quality and style vary. |
| Images | [Wikimedia Commons](https://commons.wikimedia.org/) | Per file (PD, CC0, CC BY, CC BY-SA) | Huge, photos available; licence must be read per file via the API. |
| Audio  | [Lingua Libre](https://lingualibre.org/) (files on Wikimedia Commons, `LL-…`) | Usually CC BY-SA 4.0, per file | Single-word recordings by native speakers, has Swedish and English. Primary audio source. |
| Audio  | Wikimedia Commons pronunciation files (`Sv-…`, `En-us-…`) | Per file | Fallback for words Lingua Libre lacks. |
| Audio  | Mozilla Common Voice | CC0 | Whole sentences, not single words; poor fit, not planned. |

Licence consequence: bundling CC BY-SA and CC BY-NC-SA material means the
**published decks are released under CC BY-NC-SA 4.0**. The repository's code stays under the MIT licence in
`LICENSE`; media keeps its own licence as recorded in `media/sources.csv`.

### Provenance rules (must follow)

- Every file under `media/` has exactly one row in `media/sources.csv` with:
  `file, source, source_url, author, licence, licence_url, retrieved_at, sha256`.
- Never add a media file without that row. `build_decks.py` fails if a
  referenced file has no provenance row or an unacceptable licence.
- `ATTRIBUTION.md` is generated from `sources.csv`, and an attribution card or
  deck description carries the same credits inside each deck.
- Prefer one image source per deck so pictures look consistent.
- Downloaded media is committed to the repo so
  builds are reproducible and offline. Keep files small: images at most
  ~512 px on the long side (PNG/SVG→PNG or WebP), audio as mono MP3/OGG.
- Content must be child-appropriate: review new images before committing.

## Working conventions for Claude

- Do not hand-edit generated files (`data/arithmetic/*.csv`, `ATTRIBUTION.md`,
  `build/`); change the script and regenerate.
- When adding words, add both `sv` and `en` in the same row; never leave one
  language empty.
- When fetching media, respect each site's API terms and rate limits, and set
  a descriptive User-Agent (Wikimedia requires one).
- Built `.apkg` files are published as GitHub Release assets, not committed.
