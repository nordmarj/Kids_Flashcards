# CLAUDE.md

Guidance for Claude (and humans) working in this repository.

## Purpose

This repository holds the **source data** (tables of strings and media files)
and the **build scripts** that turn that data into [Anki](https://apps.ankiweb.net/)
flashcard decks for **young children**.

The repo is the single source of truth. Decks (`.apkg` files) are build
outputs, never edited by hand.

Audience: children who are **just learning to read and count, up to around
ten years old**. The youngest may barely read, so cards must be visual and
short, and every word card is spoken aloud; content can grow harder for
older children (longer words, larger numbers) via separate levelled decks.

## Deck categories

1. **Arithmetic** – sums such as `3 + 4 = ?`, in easy-first subdecks:
   addition (two terms 0–20, then a sample of three-term sums to 20),
   subtraction (within 10/20, then negative answers, then minus a negative),
   multiplication tables 0–20, and division (within 20 with whole answers,
   then the tables read backwards). Every sum has a multiple-choice card and a
   typing card. Small sums show a counting picture (ten-frames, number line,
   dot rows, division as sharing onto plates), drawn as inline SVG at build
   time, so arithmetic needs no media files. Arithmetic rows are generated by
   a script into a table rather than typed by hand, so the table stays
   reviewable and the deck stays stable.
2. **Picture → word (multiple choice)** – a picture is shown with several
   candidate words; the child picks the one that matches. The back reveals the
   correct word and plays its audio.
3. **Shapes** – 19 geometric shapes (`data/shapes/shapes.csv`), each with a
   name → picture and a picture → name multiple-choice card, in every
   language. Shapes are drawn as inline SVG, so they need no image files.

4. **Geography** – flags and maps ↔ place names (multiple choice), for
   countries, continents and a few regions (Jens, 2026-10-18). One table per
   topic in `data/geography/` ties each place's ARASAAC flag and/or map to its
   name and recording in every language. A place is kept when at least one
   language has a recording of its name; each language's geography deck
   (`Geografi::Flaggor`, `Geography::Maps`, …, one package per language)
   holds everything that language has. No card without a recording. Every
   flag and map gets a picture → name and a name → picture card (Jens,
   2026-10-18), both multiple choice. Names
   come from Wikidata labels (ARASAAC has no Swedish place keywords) and
   ARASAAC keywords, matched to recordings by file name.

More categories may be added later; each category gets its own table(s) and
note type.

## Languages

Word cards are built in **Swedish (`sv`), English (`en`), German (`de`),
Swahili (`sw`), Spanish (`es`) and French (`fr`)** (ISO 639-1 codes).

- One concept table holds one row per concept (e.g. "cat") with every
  language's word side by side, so the languages can never drift apart.
- A concept may exist in only one language (Jens, 2026-10-08): its other
  word and recording are left empty and it only appears in that language's
  deck. There is no word cap (Jens lifted the 1,000-word cap on
  2026-10-09): every kid-friendly ARASAAC picture with a recording goes in,
  and every word must suit the target audience.
- Each language is built as its **own deck tree** from that shared table:
  a top-level deck per language, a deck per card type under it, and a
  subdeck per topic, e.g. `Svenska::Ord::Djur`, `English::Words::Animals`,
  `Deutsch::Wörter::Tiere`, `Kiswahili::Maneno::Wanyama`,
  `Español::Palabras::Animales` and `Français::Mots::Animaux`.
  Later card types (such as sentences) become siblings of `Ord`/`Words`.
  The concept `level` becomes a tag (`level1`, `level2`), not a subdeck.
- Arithmetic is language-neutral and lives in its own `Maths` deck tree
  (`Maths::1 Addition::…`). The shapes stay there too, one subdeck per
  language (`Maths::5 Shapes (English)`, `Maths::6 Former (svenska)`,
  `Maths::7 Formen (Deutsch)`, `Maths::8 Maumbo (Kiswahili)`,
  `Maths::9 Formas (español)`, `Maths::9 Formes (français)`), as a deliberate
  exception to the per-language trees, because they are a maths topic.
  `build_decks.py --lang` builds only the chosen languages' shape subdecks.
  Swahili has no word for diamond, octagon or semicircle in the
  dictionaries, so those shapes are left out of its subdeck.
- Swedish text must keep `å ä ö`, German `ä ö ü ß`, Spanish `á é í ó ú ñ`
  and French `é è ê à ç œ`; all files are UTF-8.
- German nouns are capitalised (`Katze`). Some German recordings include the
  article (`die Tasse`), and the card then shows it too.
- The Swahili words were translated by Claude and matched to recordings by
  file name. Each one is checked against open dictionaries (English
  Wiktionary via kaikki.org, FreeDict) and dropped if the dictionary gives
  another meaning; they have not yet been checked by a Swahili speaker.
- Spanish and French words come from ARASAAC's own Spanish and French
  keywords, matched to Commons recordings by file name and reviewed by hand
  (verbs, wrong senses and words that would make two choices in a topic
  correct were swapped or dropped). Commons has far fewer Spanish than
  French single-word recordings, so the Spanish deck is smaller.
- The written word always matches exactly what its recording says. If the
  recording says `katt`, the card shows `katt`; if it says `en katt`, the card
  shows `en katt`. Adjust the text to the audio, never the other way round.

### Word selection: media first

Every word card has **an image and a recording of the word**. Words are
chosen so that both can be sourced: a concept is only added to a concept
table once `fetch_media.py` has found an acceptable ARASAAC image and a
recording in at least one language, and the recording must name what that
ARASAAC picture shows. Concepts missing them stay out (they may be listed in
`data/candidates/` while searching). `build_decks.py` fails if a concept row
lacks `image`, has a word without its recording (or a recording without its
word), or has no language at all.

Audio is always a real human recording; synthetic (TTS) voices are not used.
Shape names are the one exception to "every card has audio": Swedish
recordings exist for only a few of them (and a few Spanish and Swahili ones
are missing), so the rest stay silent until a real recording is found.

## Repository layout

```
data/
  concepts/<topic>.csv      # one row per concept: id, sv, en, de, sw, es, fr, level, image, audio_<lang>...
  candidates/words.csv      # words being considered, before media is confirmed
  candidates/coverage.csv   # generated by check_coverage.py: which media exists per word
  candidates/media_picks.csv  # generated by fetch_media.py pick, may be hand-edited
  arithmetic/<range>.csv    # generated: id, question, answer, distractors
  shapes/shapes.csv         # id, <lang>..., level, audio_<lang>...; pictures drawn by shape_pictures.py
  geography/<topic>.csv     # generated: id, <lang>..., level, flag, map, audio_<lang>...
  candidates/geography_picks.csv  # generated by fetch_geography.py pick, may be hand-edited
media/
  images/<id>.png           # downloaded pictures (flag_<id>.png, map_<id>.png for places)
  audio/<lang>/<id>_<lang>.mp3  # downloaded pronunciations (cat_sv.mp3, cat_en.mp3;
                                # place names geo_<id>_<lang>.mp3)
  sources.csv               # provenance + licence for every media file (see below)
scripts/
  check_coverage.py         # looks up which candidate words have all media
  fetch_media.py            # picks and downloads media, records provenance
  fetch_geography.py        # same for the geography flags, maps and place names
  gen_arithmetic.py         # writes data/arithmetic/*.csv
  arithmetic_pictures.py    # counting pictures (SVG) for arithmetic cards
  shape_pictures.py         # shape pictures (SVG)
  word_decks.py             # picture → word decks; writes ATTRIBUTION.md
  geography_decks.py        # flag/map → place name decks
  build_decks.py            # reads data/ + media/, writes build/*.apkg
templates/<note_type>/      # Anki card HTML/CSS/JS per note type (arithmetic,
                            # picture_choice, shapes, geography): front/back HTML, style.css
build/                      # svenska, english, deutsch, kiswahili, espanol, francais,
                            # geography_<lang>, maths .apkg; git-ignored
ATTRIBUTION.md              # generated credits for all bundled media
```

Media filenames carry the language (`cat_sv.mp3`) because Anki keeps all media
in one flat folder, so recordings in different languages must not share a name.

`level` is 1 for a child's very first words and 2 for slightly harder ones.

Tables are **CSV, UTF-8, comma-separated, with a header row** so they diff well in git and open in any
spreadsheet.

Concept `id`s are lowercase English slugs (`cat`, `fire_truck`) and must
never change once published; they feed Anki GUIDs (see below).

## Tooling

- **Python 3** with [genanki](https://github.com/kerrickstaley/genanki) (MIT)
  to generate `.apkg` files.
- genanki rules that matter here:
  - Model (note type) IDs and deck IDs are hard-coded constants, chosen once
    and never changed; changing them makes Anki treat the deck as new.
  - Each note gets a stable GUID derived from the concept `id` and language
    (`genanki.guid_for(...)`), so re-importing an updated deck updates
    existing cards instead of duplicating them and keeps the child's progress.
  - Media files are passed via `Package.media_files`; filenames referenced in
    fields must be bare basenames (`<img src="cat.png">`, `[sound:cat_sv.mp3]`).
- **Multiple choice** is implemented in the card template with a little
  JavaScript (shuffle the choices, highlight the tapped answer) so no Anki
  add-on is required. Templates must be tested on
  Anki desktop, AnkiDroid and AnkiMobile, since those are where kids use it.
  Distractor words come from other concepts in the same topic.
- Keep dependencies minimal; pin them in `requirements.txt`.

## Media sourcing and licensing

Media is fetched **automatically** from repositories whose licences allow
**noncommercial redistribution**. This project is noncommercial, so
NonCommercial (NC) licences are acceptable, but every file must still meet its
licence's terms (attribution, ShareAlike).

Acceptable licences: CC0 / public domain, CC BY, CC BY-SA, CC BY-NC,
CC BY-NC-SA, MIT/Apache-style. Not acceptable: anything with NoDerivatives
(ND) if we resize/convert, "personal use only", unclear or missing licence.

Candidate sources:

| Kind   | Source | Licence | Notes |
|--------|--------|---------|-------|
| Images | [ARASAAC](https://arasaac.org/) pictograms | CC BY-NC-SA 4.0 | Made for children/AAC, consistent style, has an API with Swedish, English, German, Spanish and French keywords (no Swahili). Primary image source. |
| Images | [OpenMoji](https://openmoji.org/) | CC BY-SA 4.0 | Consistent emoji style, good for animals/food/objects. |
| Images | [Openclipart](https://openclipart.org/) | CC0 | No attribution needed; quality and style vary. |
| Images | [Wikimedia Commons](https://commons.wikimedia.org/) | Per file (PD, CC0, CC BY, CC BY-SA) | Huge, photos available; licence must be read per file via the API. |
| Audio  | [Lingua Libre](https://lingualibre.org/) (files on Wikimedia Commons, `LL-…`) | Usually CC BY-SA 4.0, per file | Single-word recordings by native speakers: Swedish, English, German, ~19,000 Spanish and ~440,000 French. Primary audio source. |
| Audio  | Wikimedia Commons pronunciation files (`Sv-…`, `En-us-…`, `De-…`, `Es-…`, `Fr-…`) | Per file | Fallback for words Lingua Libre lacks. |
| Audio  | Wikimedia Commons `Sw-ke-…` files | CC BY-SA 4.0 | About 16,700 Kenyan Swahili words, one speaker (Waithera Were). Primary Swahili source; Lingua Libre has only ~100 Swahili files. |
| Audio  | Mozilla Common Voice | CC0 | Whole sentences, not single words; poor fit, not planned. |

Licence consequence: bundling CC BY-SA and CC BY-NC-SA material means the
**published decks are released under CC BY-NC-SA 4.0**. The repository's code stays under the MIT licence in
`LICENSE`; media keeps its own licence as recorded in `media/sources.csv`.

### Provenance rules (must follow)

- Every file under `media/` has exactly one row in `media/sources.csv` with:
  `file, source, source_url, author, licence, licence_url, retrieved_at, sha256`.
- Never add a media file without that row. `build_decks.py` fails if a
  referenced file has no provenance row or an unacceptable licence.
- `ATTRIBUTION.md` is generated from `sources.csv`, and an attribution card or
  deck description carries the same credits inside each deck.
- Prefer one image source per deck so pictures look consistent.
- Downloaded media is committed to the repo so
  builds are reproducible and offline. Keep files small: images at most
  ~512 px on the long side (PNG/SVG→PNG or WebP), audio as mono MP3/OGG.
- Content must be child-appropriate: review new images before committing.

## Working conventions for Claude

- Do not hand-edit generated files (`data/arithmetic/*.csv`, `data/geography/*.csv`, `ATTRIBUTION.md`,
  `build/`); change the script and regenerate.
- When adding words, fill in every language that has a recording in the
  same row; leave a language empty only when it has none.
- When fetching media, respect each site's API terms and rate limits, and set
  a descriptive User-Agent (Wikimedia requires one).
- Built `.apkg` files are published as GitHub Release assets, not committed.
  The released maths deck is the Swedish and English build
  (`build_decks.py --lang sv en`, Jens 2026-10-10), since every language
  combination can't be prebuilt; the word and geography decks are released
  per language.
